Issue body actions

Version: Deno 2.9.5

    deno 2.9.5 (stable, release, aarch64-apple-darwin)
    v8 15.0.245.2-rusty
    typescript 6.0.3
    

`import defer` ([TC39 stage 3](https://github.com/tc39/proposal-defer-import-eval)
) is accepted by the runtime and by `deno check`, but every bundling path rejects it with a parse error. Compiling the same file _without_ `--bundle` works, which narrows it to the bundler.

Reproduction
------------

Minimal repo: [https://github.com/xpr0gamers/deno-bundle-import-defer](https://github.com/xpr0gamers/deno-bundle-import-defer)

```ts
// src/deferred.ts
console.log('   [deferred.ts was evaluated]');
export const value = 'deferred value';

// src/main.ts
import defer * as deferred from './deferred.ts';

console.log('1. Program started. The deferred module must NOT be evaluated yet.');
console.log('2. Touching the namespace now — evaluation happens on this line:');
console.log('3. value =', deferred.value);
```

| command | result |
| --- | --- |
| `deno run src/main.ts` | works, evaluation is correctly deferred to first access |
| `deno check src/main.ts` | exit 0 |
| `deno compile --output dist/repro-plain src/main.ts` | works, produces the executable |
| `deno compile --output dist/repro-bundled --bundle src/main.ts` | **fails** |

Expected
--------

`deno compile --bundle` produces the executable, like the run without `--bundle` does.

Actual
------

    Warning deno compile --bundle is experimental and may change.
    error: Expected "from" but found "*"
        at file:///.../src/main.ts:3:13
    error: bundling failed
    

Column 13 is the `*`, so the parser appears to read `defer` as a default-import binding and then reject the namespace form. `Deno.bundle()` fails identically:

    { "text": "Expected \"from\" but found \"*\"", "location": { "line": 1, "column": 13, "suggestion": "from" } }
    

For contrast, the runtime output shows the deferral working — the side effect appears only after line 2:

    1. Program started. The deferred module must NOT be evaluated yet.
    2. Touching the namespace now — evaluation happens on this line:
       [deferred.ts was evaluated]
    3. value = deferred value
    

Likely cause
------------

The bundler shells out to a downloaded esbuild binary, which on this machine is 0.25.5:

    $ ~/Library/Caches/deno/dl/esbuild-0.25.5/esbuild-darwin-arm64 --version
    0.25.5
    

That binary reproduces the error on its own, with Deno out of the picture:

    $ printf 'import defer * as ns from "./x.js";\nconsole.log(ns);\n' > d.ts
    $ esbuild-darwin-arm64 --bundle d.ts --outfile=/dev/null
    ✘ [ERROR] Expected "from" but found "*"
    
        d.ts:1:13:
          1 │ import defer * as ns from "./x.js";
            │              ^
            ╵              from
    

esbuild added `import defer` in **0.25.7** (its `CHANGELOG-2025.md` documents both `import defer * as foo from "<specifier>"` and `import.defer("<specifier>")`; see [evanw/esbuild#4238](https://github.com/evanw/esbuild/issues/4238)
). The pinned 0.25.5 predates that by two patch releases, so bumping the downloaded esbuild may be all that is needed.

Why it is worth fixing
----------------------

Because `deno run` and `deno check` both accept the syntax, the failure only surfaces when producing a standalone executable — that is, at release time rather than during development.
